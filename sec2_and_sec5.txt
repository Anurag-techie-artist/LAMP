research focuses on deﬁning the architecture of the fog
computing [ 10, 11, 12, 13], assessing its suitability for the
IoT [ 14, 15, 16], introducing platforms for simulating this
environment [ 17, 18, 19], considering safety and privacy

One of the most important issues in fog computing is place-

to the optimal solution, with efﬁcient results the algorithm

resources on the network. This algorithm maps the application
modules and fog devices according to the existing requirements
and capacity. They have also shown that in a delay, a cloud-
fog approach is more effective than the cloud-only approach.
But they focus more on reducing the use of resources for
distributed applications and the delay is not taken. Gupta et
al.[2] have introduced ifogsim to model and simulate the fog
environment, the IoT and the edge of the network. In this
simulator, you can evaluate resource management techniques
based on service quality criteria, such as delays in various work
volumes in the fog.
Our current work and the work of others to enable the use
of fog computing as a platform provide better service to
the end user and increase the network efﬁciency of existing
infrastructure and intelligent technology scenarios.

V. EVALUATION RESULTS AND ANALYSIS
We employ iFogsim simulator to evaluation and investiga-
tion of LAMP algorithm. The iFogsim was developed by Gupat
et al . [ 2] based on cloudsim. IoT applications run on network
topologies provided by iFogsim. A summary of the experimen-
tal setup can be found in Tables III and IV. The simulation runs
on topologies with 2, 3, and 4 fog devices. Each fog device
supports 2, 4, 6 and 8 end devices. We assume each end device
represents an application. The LAMP algorithm in terms of
delay, cloud energy consumption, Fog energy consumption,
cloud cost, and total network usage compares with four other
algorithms include Cloud-Only Module Placement (COMP),
Lower-Bound Module Placement (LBMP) which is introduced
in [ 3], Simulated-Annealing Module Placement (SAMP) in
[9] and Edge-Wards Module Placement (EWMP) algorithm.
The simulation results show the performance of the proposed
algorithm in comparison with all network topologies on the
comparison criteria in, especially when the number of appli-
cations increases. As can be seen in Fig 3, when is the number
of applications in each fog devices is less than 4, the EWMP
algorithm responses are in the good condition. But, when
the number of these applications increases per fog device,
its performance drops sharply. V ersus, LAMP algorithm better
results at the highest number of applications and has a very
favorable effect and can be seen that the delay has a signiﬁcant
decrease.
As can be seen in Fig 4, With placing module near-application
devices, the algorithm has been able to reduce the average
delay by up to 40 % for the COMP and up to 20 % for
other algorithms. Of course, as you can see, the effect of
the proposed algorithm is more evident when the number
of devices in the network is limited and the number of
applications increases.
