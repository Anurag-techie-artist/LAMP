Abstract—The delay in the transmission of data to the cloud
and their return impacts on applications performance. Hence, Fog
computing with transferring the cloud services to the edge of the
network causes to decrease the delay in services of applications
such as healthcare, online games, and other IoT applications.
Moreover, Fog computing reduces the cost and energy consump-
tion of cloud data centers. One of the most important issues in fog
computing is the placement of modules of IoT application on fog
devices at the edge of the network to have a minimum of latency
and the highest performance. In this paper, we propose a latency-
aware module placement algorithm in Fog-Cloud environment,
called LAMP, which is an exploratory algorithm for the optimal
application modules placement into devices. LAMP provides less
delay for IoT applications with reducing the distance between
the host device modules. Consequently, improves the functionality
of IoT applications. We use iFogsim simulator and evaluate the
proposed algorithm compared to four strategies of placing in the
fog-cloud environment. According to our results of the simulation,
the efﬁciency of the proposed algorithm is guaranteed.
Keywords— Fog computing, Cloud computing, Internet of
Things (IoT), resource management, Healthcare, module place-
ment.
I. INTRODUCTION
The Internet of Things (IoT) is expanding rapidly because
its purpose is to connect any object to the Internet to talk to
each other [ 1]. According to the report in [ 2, 3], predicted by
the year 2025 about 1 trillion devices will be connected to the
Internet which is the threat to storage and computing systems.
Because which objects and IoT applications connected to the
internet will produce a lot of data. One way to deal with
this problem is cloud computing which provides resources
and infrastructures for storing and computing IoT applications.
However, in delay-sensitive services, sending data to the cloud
and returning their response can reduce the value of data.
consequently, affect the effectiveness of cloud computing. To
resolve this shortcoming, the new concept called Fog Comput-
ing was raised. [ 4, 5]. Fog computing is a system between the
cloud and IoT that extends cloud services to the network edge.
In fog computing, computing performs by physical devices in
real-time because these devices (fog devices) distributed in
the network edge and are close to the user[ 6, 7, 8]. Several
applications put in the fog devices that each of which includes
several modules. Placing the application modules at the start
of the network is said static placement and when the network
is active and the placement of modules in the network is
optimized is said dynamic placement. Fog devices near the
edge of the network such as micro-data centers, routers, access
points, gateways and etc, do not have enough resources to host
all the modules of IoT applications (or heterogeneous modules
of different applications for that topic).
Hence, in this paper, we introduce a latency-aware strategy
for placing modules based on the hierarchical structure of
fog computing, called LAMP , which with the optimal use
of resources in cloud data centers and fog devices reduce
the response time. This paper evaluates the performance of
LAMP algorithm compare to Cloud-Only Module Placement
(COMP), Lower-Bound Module Placement (LBMP) which
is introduced in [ 3], Simulated-Annealing Module Placement
(SAMP) in [ 9] and Edge-Wards Module Placement (EWMP)
algorithm scale simulations, by using iFogsim simulator [ 2].
This simulator employs for simulation of resource management
techniques in the IoT, Edge and Fog Computing Environments.
Our contributions in this paper are:
1) Introducing an algorithm for placing application modules
on fog-cloud devices based on fog-clod hierarchical struc-
ture.
2) Efﬁcient use of fog-cloud resources.
3) Evaluating the proposed algorithm using the health-care
application in compression with four strategies for placing
in the fog-cloud environment.
The rest of the article is as follows: Section II, presents a
summary of related studies, and section III introduces the
model of the system and the application of healthcare. In
section IV, the main problem and the proposed algorithm
displays and section V illustrates the implementation and
evaluation of simulation results. Finally, section VI describes
the conclusions and future work.

III. SYSTEM AND APPLICATION MODULE
DESCRIPTION
The fog computing is expanded by the traditional cloud
model, which can be applied in architectural implementations
in several layers of network technology [ 4]. In this paper, we
consider the three-level hierarchical model shown in Fig. 1. As
you see, at the ﬁrst level, the cloud data center is located
that is considered as unlimited resources on the network. The
middle layer is fog, and the ﬁnal layer of this hierarchy is IoT
devices such as sensors and devices that are in contact with
the end user. In this architecture, the layer of fog devices can
include more layers. Any element in a network that is capable
of hosting applications is considered as a fog device [ 28]. Each
fog device has a speciﬁc and limited computing capability (due
to hardware limitation of resources per device), which in turn
forms the resources available on that layer [ 3].
A. APPLICATION MODULE
We consider IoT applications based on the Distributed Data
Flow (DDF) model because provides better results for multi-
component applications [ 3]. Also, We employ to implement
these modules in the proposed algorithm from the Directed
Fig. 1. Hierarchical architecture of Fog-Cloud computing
Acyclic Graph (DAG) model. Because application modules
are interdependent. After inserting the input module, the cor-
responding data ﬂow identiﬁes the next module for placement.
Additionally, if a module is assigned to its own resources,
it is expected that the module will execute its operation at
a ﬁxed time. Each application has an input module, which
informs the program’s basic information such as authentica-
tion, a frequency of data signal measurement, metadata of
the next application modules, and their interconnection with
the system through this module. After the deployment of all
modules, the input module communicates directly with IoT
application with a particular program to capture sensitive data
signals and delivers its data to the subsequent modules for
further processing. After processing by other modules, the
response is applied by the input module to the actuators. Since
the input module plays the role of the root component for
applications and is directly related to sensors and actuators, it
should be placed on low-end devices. The applications work
on the Sense-Process-Actuate model, which is the information
collected by the sensors that are issued as the data stream and is
processed by the application modules running in the fog layer.
Then the commands (or outputs) are sent to the actuator and
ﬂow processing model. The application modules, which are
running on the fog layer, process the data ﬂow of the sensors
and collected information forward to the cloud data center for
the Restoration. Applications can be implemented in different
network topologies and there is a graphical user interface in the
iFogsim simulator for designing or adding network topology.
In this article, we have evaluated applications from [ 24] which
introduced a model of healthcare applications including main
interface, sensor analyzer and cloud storage. As shown in
Fig.2, the BSN functional model, which is built with fog
architecture, has a sensor node, two actuators, and three main
processing modules. They show the input-output relationship
between the modules. The function of each module is as
follows:
Interface: This module receives and conﬁrms the raw ECG
signals generated by the sensors. It rejects any possible discrep-
ancy between the data and examines their synchronization. At
this stage, data management includes data alert, automatic data
correction, data transfer, and data separation. The information
is then transferred to the sensor analyzer module to further
process and analyze data. This module also updates current
patient’s ECG reports.

V. EVALUATION RESULTS AND ANALYSIS
We employ iFogsim simulator to evaluation and investiga-
tion of LAMP algorithm. The iFogsim was developed by Gupat
et al . [ 2] based on cloudsim. IoT applications run on network
topologies provided by iFogsim. A summary of the experimen-
tal setup can be found in Tables III and IV. The simulation runs
on topologies with 2, 3, and 4 fog devices. Each fog device
supports 2, 4, 6 and 8 end devices. We assume each end device
represents an application. The LAMP algorithm in terms of
delay, cloud energy consumption, Fog energy consumption,
cloud cost, and total network usage compares with four other
algorithms include Cloud-Only Module Placement (COMP),
Lower-Bound Module Placement (LBMP) which is introduced
in [ 3], Simulated-Annealing Module Placement (SAMP) in
[9] and Edge-Wards Module Placement (EWMP) algorithm.
The simulation results show the performance of the proposed
algorithm in comparison with all network topologies on the
comparison criteria in, especially when the number of appli-
cations increases. As can be seen in Fig 3, when is the number
of applications in each fog devices is less than 4, the EWMP
algorithm responses are in the good condition. But, when
the number of these applications increases per fog device,
its performance drops sharply. V ersus, LAMP algorithm better
results at the highest number of applications and has a very
favorable effect and can be seen that the delay has a signiﬁcant
decrease.
As can be seen in Fig 4, With placing module near-application
devices, the algorithm has been able to reduce the average
delay by up to 40 % for the COMP and up to 20 % for
other algorithms. Of course, as you can see, the effect of
the proposed algorithm is more evident when the number
of devices in the network is limited and the number of
applications increases.
and it is clear that, according to Fig. 5, energy consumption in
fog increases, but given the only 5% increase in fog computing
(on average), the proposed algorithm is acceptable in this
regard. Network usage means using the network resources,

VI. CONCLUSIONS AND FUTURE WORKS
Fog computing has been designed to reduce the challenges
of cloud computing such as delays, energy consumption, and
so on, which has the potential to support IoT applications.
One of the main challenges of fog computing is to place
the IoT application modules in the cloud-fog environment. In
this paper, we presented the latency-aware algorithm using the
position of the fog devices. We have introduced key features
that affect response latency in IoT applications, while the
expansion of applications in this environment was considered.
The present paper focuses on static gesture. As a future work,
we will examine the dynamic conditions of the placement so
that we can ﬁnd methods for ﬁnding a high and low load
device in the network and with the migration of modules at
the network level and schedules of fog devices increase the
network performance.
